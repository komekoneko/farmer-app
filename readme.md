# 🌱 推し農家（Oshi Nouka）

商品に貼られた QR コードから、その野菜を作った農家さんのページに直接アクセスできる Web アプリです。

## 概要

スーパーや市場で買った野菜の袋に貼られた QR コードを読み取ると、その農家さんのプロフィールページが開きます。農家さんの人柄や、どこで買えるか（販売場所）を知ることで、消費者と地域の農家をより近づけ、地産地消の活性化を目指すプロジェクトです。QR コードは一覧のトップページではなく、農家さん個人のページに直接つながる導線にしています。

## 背景

日本では、海外からの食料輸入や大規模企業農園の登場、物価高騰による安い野菜への需要増などにより、個人農家の経営が厳しくなっています。高齢化による廃業も増えています。また、ドラッグストアやコンビニの拡大で市場や商店街の八百屋に足を運ぶ機会が減り、農家と消費者の距離が以前より遠くなっています。

そこで、生産者を軸に「誰が作ったか」「どこで買えるか」を伝えることで、消費者が特定の農家を継続的に応援できる関係づくりを目指しました。

## 主な機能

**農家プロフィールページ**
- 農家の顔写真・農園名・場所
- 吹き出し形式のコメント（農家さんが話しかけているような表示）
- 販売場所カード（店名・出品日・Google Map リンク）
- 主な取り扱い野菜（野菜名から絵文字を自動で付与）
- 「他の農家も見る」で一覧へ、「編集する」で編集画面へ

**トップページ（農家一覧）**
- 登録農家をカード形式で一覧表示
- 名前・農園名・地域での絞り込み検索
- カードをタップでその農家のプロフィールへ

**編集画面**
- 農家さん自身がプロフィールを編集する画面（デモ）
- 農園名・名前・場所・コメントの入力
- 農家ごとに切り替え表示

**QR コード連携**
- 各農家ページの URL を QR コード化し、商品パッケージに貼る想定
- 読み取ると該当農家のページへ直接アクセス

## 使用技術

- React
- Vite
- CSS
- react-router-dom

データはバックエンドを使わず、JSON ファイルで管理しています。

## 工夫した点

**QR から個人ページへの直接導線**
一般的な Web サービスはトップページから各ページへ遷移しますが、本アプリは商品の QR コードから特定の農家ページ（`/farmer/:id`）へ直接入る導線を前提に設計しました。そこから一覧ページへ回遊できるようにしています。

**URL による農家の切り替え**
`react-router-dom` の `useParams` で URL の id を受け取り、その id に一致する農家を JSON から探して表示しています。プロフィール・編集の両方をこの仕組みで切り替えるため、農家が何件増えてもコードを変えずに対応できます。

**入力負担を減らす絵文字の自動付与**
取り扱い野菜は、農家さんが絵文字まで入力しなくて済むよう、野菜名だけを登録すれば対応する絵文字が自動で付く仕組みにしました。対応表にない野菜には汎用の芽アイコンが付き、表示が崩れないようにしています。

**バックエンドを使わない構成の選択**
発表・デモの段階では農家データが動的に更新される必要性が低いと判断し、Firebase などのバックエンドを使わず JSON ファイルでデータを管理する構成にしました。開発の複雑さを抑えつつ、将来的にバックエンドへ移行できる余地を残しています。

## ディレクトリ構成

```
src/
├── App.jsx                    # ルーティング設定
├── data/
│   └── farmers.json           # 農家データ
└── components/
    ├── FarmerList.jsx         # トップpage（農家一覧・検索）
    ├── FarmerList.css
    ├── FarmerProfile.jsx      # 農家プロフィールページ
    ├── FarmerProfile.css
    ├── FarmerEdit.jsx         # プロフィール編集画面
    └── FarmerEdit.css
public/
└── images/                    # 農家の写真
```

## 動かし方

```bash
# 依存パッケージをインストール
npm install

# 開発サーバーを起動
npm run dev
```

起動後、ターミナルに表示される `http://localhost:5173` をブラウザで開くと使えます。
